# HDR 控制中心 0.29（启动与开关响应优化）

[下载最新版本 0.29](https://github.com/Forejant/HDR-Control-Center/releases/tag/v0.29) · [版本记录](CHANGELOG.md)

源码构建：Windows PowerShell 执行 `.\build.ps1`，使用系统自带 .NET Framework 4.8 C# 编译器，无需安装 SDK。构建后运行 `HdrControlCenter.exe`。发布 ZIP 包含预编译程序、源码和说明。

面向 Windows 的便携式系统托盘工具，中文界面。双击 `HdrControlCenter.exe` 即可运行，无需安装 .NET SDK，无需管理员权限。要求 Windows 10/11 x64 与 .NET Framework 4.8（Windows 11 已内置）。Windows 11 24H2 优先使用独立 HDR API。

## 0.29 启动与开关响应优化

初始界面集中完成布局，减少逐个添加控件的重复计算。首次读取状态时，显示器与 HDR 信息先发布到界面，Windows 设置和 NVIDIA 的 UI Automation 状态随后后台补充。同一屏幕、相同 DPI、窗口边界及内容尺寸不变时，重复托盘唤起复用已有布局；主题、DPI、屏幕、窗口大小或内容尺寸变化仍执行原有布局。保留遮罩、完整首帧绘制和唤起毛玻璃准备。

HDR 切换移除固定 400 ms 延迟，立即回读；未达到目标时每 50 ms 重读，最多约 1.5 秒，并继续校验显示器连接身份。RTX 在切换后立即检查应用按钮，应用后立即检查保存结果，未就绪才等待后重试；事务直接读取已确认的视频页面，避免再次找窗口。保存配置在切换前已经等于目标时，不能把同值视为本次保存完成，继续使用页面保存确认。杜比视界展开 HDR 项后立即查找复选框，未加载时由原有就绪循环等待。

HDR、杜比视界和 RTX 动作在自身结果确认后更新对应状态，结束加载动画并允许继续操作，其他状态刷新随后后台完成。保留 NVIDIA 单次自动打开/关闭、待保存修改保护、结果回读、用户主动收起后不重新弹出。控制面板启动和驱动应用本身的耗时仍取决于系统。

布局批处理依据 [Microsoft SuspendLayout/ResumeLayout](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.control.resumelayout)；HDR 回读使用 [DisplayConfigGetDeviceInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-displayconfiggetdeviceinfo)。沿用用户此前要求，本轮仅编译打包，没有运行测试或更改真实显示/驱动开关，未测量实际提速幅度。历史测试记录不代表 0.29 的运行结果。

## 0.28 唤起材质准备

调整隐藏窗口的唤起顺序：在 DWM 遮罩下完成前景激活，确认激活后重新准备 Acrylic 背景，绘制整个控件树并提交合成，再解除遮罩。移除成功唤起后的第二次激活，减少先呈现未激活纯色、随后切换材质的机会。保留 0.27 的纯色强度、同一窗口句柄、点击外部收起及现有功能。Windows 拒绝遮罩期间前景激活时仍允许一次揭示后的补救激活，不伪造系统焦点。

合成提交参考：[Microsoft DwmFlush](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmflush)；背景使用 [DWM_SYSTEMBACKDROP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type)。合成等待只用于隐藏窗口唤起，不用于滑块更新或开关动画。沿用用户要求，本轮仅编译打包，未运行测试，首次显示的实际材质时序待用户桌面确认；历史验证不证明本轮视觉修复效果。

## 0.25 实时亮度与自动收起

拖动 SDR 亮度滑块时立即提交变化；上一笔写入完成后，马上继续写入最新位置，不再等待固定的 25–30 ms 间隔。慢速驱动响应期间合并中间值，保持最多一笔写入；松手后再次确认最终亮度。写入直接校验所选显示器的身份和 HDR 状态，避免每次重新枚举所有显示器。显示器拔插或切换后，旧显示器的失败不会丢弃新显示器的待应用值。

背景主题色和卡片填充只小幅增强，减少过度透色，保留原生 Acrylic 毛玻璃、实体文字和圆角。Windows 的原生 Acrylic 会随窗口激活状态改变材质；普通失焦时现在自动收起控制中心，保留托盘运行，单击托盘再次打开。

点击其他窗口时收起控制中心。RTX、杜比视界应用过程中，设置页自动获得焦点仍保留控制中心；如果用户主动点击外部窗口，则即使正在应用也收起，操作结束不重新弹出。控制中心自己的对话框、下拉菜单、托盘菜单和拖动中的滑块不会触发误收起。外部点击观察只在面板可见期间运行，不拦截输入。

本机真实 SDR 亮度的小幅往返写入已回读确认，单次约 3–6 ms，结束后精确恢复原始白电平 4000；这是本机测量，不代表所有驱动的响应时间。新增回归验证立即写入、拖动中连续提交、39 次中间请求合并、最终确认、跨显示器失败恢复、失焦收起及应用期间主动收起；字体、动画、720 次亮度更新、36 次唤起和托盘回归全部通过。交互桌面另外检查了稍强底色的实际毛玻璃效果。本轮未切换真实 HDR、杜比视界或 RTX 状态，未修改开机启动或系统透明设置。结果见 `验证结果.txt`。

`--realtime-popup-test 路径.txt --wait-for-focus` 使用示例数据检查实时写入队列与真实窗口焦点/输入观察生命周期；交互桌面中需激活测试窗口后开始。`--brightness-live-test 路径.txt` 会小幅改变真实所选 HDR 显示器的 SDR 亮度并在 finally 中恢复精确原值。静态预览 PNG 只展示布局与字体，不包含实时桌面毛玻璃。

升级前从旧版托盘菜单退出，再解压运行新版，原配置继续沿用。

## 0.24 字体与背景修复

修复透明客户区的文字锯齿、边缘发白和透明信息丢失：文字先在独立的 32 位预乘 Alpha 图层上使用灰度抗锯齿绘制，再保留透明度复制到窗口。标题、正文、亮度读数、复选框、普通按钮和选择框文字采用一致的抗锯齿方式。卡片、开关、滑块及容器的透明绘制也保留有效 Alpha；按钮动画继续局部重绘。该方式不依赖系统是否启用了 ClearType，不改变字体或系统字体平滑设置。参考：[Microsoft TextRenderingHint](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.text.textrenderinghint)、[DWM 透明客户区](https://learn.microsoft.com/en-us/windows/win32/dwm/customframe)。

修复毛玻璃被固定灰底遮盖的原因：自定义标题栏此前拦截了 WM_NCACTIVATE，未让 DWM 得知窗口已激活。现在保留激活处理，并用 -1 参数阻止旧标题栏绘制，整个窗口继续保持一体圆角外观。降低主题底色和卡片的遮盖强度，使用原生 Windows 11 Desktop Acrylic 模糊背景；保持文字与按钮实体清晰。没有采用整窗透明度、色键或额外的隐藏/重开过程。窗口失焦时材质可随 Windows 原生 Acrylic 变为实色，重新激活恢复毛玻璃。透明效果关闭、高对比度或接口不支持时继续使用实色主题。

本机真实桌面用独立彩色条纹背景检查了深浅主题：窗口能透出背景颜色，背景细线被模糊；静态导出预览用于检查原始分辨率的字体和排版。文字 Alpha/抗锯齿检查覆盖 96/144/192 DPI，1000 次透明表面复制没有增加 GDI 对象；三屏 96/144/168 DPI 的动画、720 次亮度更新、36 次唤起、托盘和窗口层级回归全部通过。本轮用示例状态验证界面，没有修改真实 HDR、SDR 亮度、杜比视界、NVIDIA 开关、开机启动或系统透明设置。结果见 `验证结果.txt`。

`--material-render-test 路径.txt` 执行字体透明度和绘图资源回归；`--material-visual-test` 打开独立背景与示例窗口，用 F6 检查深浅主题，关闭示例窗口退出。升级前从旧版托盘菜单退出，再解压运行新版，原配置继续沿用。

## 0.23 开关动效与毛玻璃

HDR、杜比视界和两项 RTX 开关加入衔接动画。应用期间圆点留在当前位置，圆点内显示旋转的加载弧；结果确认后停止旋转，再以约 220 ms 的缓出动画移动到新状态。失败时清除加载效果，保留确认过的状态。重复点击被阻止；动画只重绘相应按钮，静止或隐藏时停止帧定时器。键盘和辅助功能操作保留，辅助功能状态包含忙碌提示。

点击 Windows HDR 设置或 NVIDIA 视频设置，正文状态显示“正在打开，请稍候…”，完成后显示页面已打开。托盘菜单使用同一提示。

整个窗口采用 Windows 11 Desktop Acrylic 背景和随主题变化的半透明色调，卡片也使用半透明填充。文字及开关保持清晰，未设置整窗 Opacity 或透明色键。保留系统圆角、拖动/缩放和首帧遮罩绘制。系统透明效果关闭、高对比度模式或背景接口不受支持时使用原有不透明主题；不修改系统透明设置。系统背景材质需要 Windows 11 22621 或更新版本，依据：[Microsoft DWM_SYSTEMBACKDROP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type)、[DWM 客户区透明绘制](https://learn.microsoft.com/en-us/windows/win32/dwm/customframe)。

真实桌面已用示例界面检查深浅主题、加载弧、完成后的圆点位置及“正在打开”提示。自动检查覆盖两主题、三种 DPI、延迟完成、失败恢复、重复点击、动画帧不重绘选择框、原生背景降级和窗口稳定；720 次亮度更新及 36 次首帧唤起回归通过。本轮未切换真实 HDR、杜比视界或 RTX 设置，驱动管线沿用 0.22。常规状态文本/布局变化仍可能引起必要的选择框重绘；加载旋转和圆点移动的动画帧不会重绘选择框。

`--visual-ui-light` / `--visual-ui-dark` 是可点击的示例界面，开关和打开页面都只模拟操作，不访问真实显示设置；F6 在预览中切换主题。`--animation-ui-test 路径.txt` 执行动画和背景回归。导出的静态 PNG 展示颜色与排版，不包含桌面合成器的实时毛玻璃效果。

## 0.22 NVIDIA 启动与视频页激活修复

修复控制面板关闭、上次停留在视频设置页时，只启动窗口却不继续切换 RTX 的问题。NVIDIA 启动时可能产生有标题的辅助窗口；旧版可能过早绑定辅助窗口，或把启动阶段当作多个控制面板。现在只选择可见、无所属窗口且包含原生导航树的设置主面板，等待主面板和右侧开关加载完成，再执行原有切换、应用及保存确认。页面等待最多 80 轮检查，检查间隔 200 ms；实际耗时还包括 Windows UI Automation 和驱动响应。

真实控制面板测试还确认：单纯向树控件发送双击消息可能只高亮项目。经典导航树现在先选中目标，再向已验证身份的树窗口发送回车激活；支持 Invoke 的控件仍优先使用 Invoke。未出现实际 RTX 开关时允许一次双击补救，已加载页面不重复激活。定向回车不移动鼠标，也不向其他应用注入全局按键。

本机真实桌面已验证关闭后启动的两项 RTX 往返切换、保存确认和自动关闭，以及从“管理 3D 设置”导航到视频页后保存修改。测试结束恢复 Super Resolution 关闭、RTX HDR 开启。控制中心在操作期间及结束后保持可见、原生置顶且位置、尺寸和窗口句柄稳定。该驱动可能在“应用”后自行关闭原先打开的 NVIDIA 窗口；工具不为此额外重新打开窗口，保存结果仍回读确认。三屏原生树控件、启动辅助窗口排除、导航策略、窗口层级和 720 次亮度拖动回归通过。结果见 `验证结果.txt`。

升级前从旧版托盘菜单退出，然后解压新版运行。配置继续沿用；本轮没有切换 Windows HDR、SDR 亮度或杜比视界。

## 0.21 NVIDIA 视频页导航修复

修复控制面板停留在其他页面时，只选中左侧“调整视频图像设置”而没有打开右侧页面的问题。优先使用导航项的 Invoke 激活动作；对于只提供选择操作的经典树控件，选中项目后向该 NVIDIA 树窗口发送双击激活。Invoke 后仍未加载页面时，也允许一次双击补救。

只有右侧实际出现可操作的 Super Resolution 或高动态范围开关，才继续快捷切换。已在视频页时不重复导航；双击已提交后只等待页面加载，避免反复点击。导航和后续开关操作绑定同一窗口身份，定向双击前检查窗口、进程、树控件及项目可见范围。保留原有待保存修改检查、单次自动启动/关闭和控制中心窗口层级保护。

新增 `--video-navigation-test 路径.txt`。同类原生树控件在三块屏幕上复现“选中但页面未打开”，修复后一次双击出现实际复选框；并覆盖已加载页面、延迟加载、Invoke 补救、失效控件和错误窗口身份。0.21 发布时没有可操作的 NVIDIA 控制面板，该版本只验证了测试夹具；0.22 的实际控制面板验证见上文。

激活机制参考：[Microsoft InvokePattern](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.invokepattern.invoke?view=windowsdesktop-10.0)、[树控件 NM_DBLCLK 通知](https://learn.microsoft.com/en-us/windows/win32/controls/nm-dblclk-tree-view)。

## 0.20 托盘点击修复

首次左键点击立即执行打开或收起；系统双击时间内的快速补点合并为一次动作，避免把刚打开的面板又收起。使用消息的原始输入时间判断，唤起绘制期间排队的补点不会在绘制完成后反向关闭窗口；不为第一次点击增加等待。检查同时覆盖计时器回绕和长时间闲置。

窗口可见性判断加入原生可见状态、最小化状态和应用 DWM 遮罩。残留遮罩或最小化窗口在一次点击中恢复，不先执行隐藏。解除遮罩有两次有界尝试并确认结果。唤起前在原有窗口层级中移到前面，完整绘制、解除遮罩后请求原生前景激活，不依赖 ContainsFocus。普通面板不会因此永久置顶；已可见但焦点在外部窗口时，独立的一次点击仍直接收起。原有 RTX 层级保护、完整首帧绘制和显示后不重排继续保留。

相关接口：[GetMessageTime](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagetime)、[SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)。Windows 对前景激活有系统限制；明确唤起会先保证普通窗口的前后顺序。

新增 `--tray-interaction-test 路径.txt`，模拟托盘回调时间，验证快速补点、独立单击、残留应用遮罩、最小化、失焦收起和再次唤起到原生前景。本机真实桌面检查通过；修改前相同检查复现快速第二次点击撤销打开。该检查使用示例状态，不更改显示或驱动设置，不等同于自动点击实际 Explorer 托盘图标。需要检查原生前景的测试请在交互桌面运行，隔离桌面不能代表前景激活结果。

`window.log` 新增托盘接受/忽略及唤起完成记录，包含原生前景句柄和应用遮罩状态，便于定位异常。

## 0.19 首帧闪烁修复

0.18 处理了显示后的移动，但窗口开始显示时，客户区及子控件的绘制过程仍可能暴露出来。0.19 使用 DWM 临时遮罩：在同一窗口句柄上完成定位、显示和整个控件树的同步绘制，提交 GDI 绘制批次后再解除遮罩。只禁用控制中心自身的显示/隐藏过渡动画。遮罩在 finally 中解除；没有新增显示后的隐藏/再打开、透明度变化、句柄重建或全局系统设置。

首帧绘制使用 [RedrawWindow 的 RDW_ALLCHILDREN / RDW_UPDATENOW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-redrawwindow)，遮罩和窗口动画使用 [Microsoft DWM 窗口属性](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)。这些步骤只在隐藏面板唤起时执行；亮度拖动继续使用原有异步写入与局部绘制。

`--popup-opening-test 路径.txt` 扩展为监测首帧：两套主题、三种屏幕 DPI 共 36 次冷启动/同屏重复/跨屏唤起，原生可见时仍有应用遮罩；客户区表面、布局、开关、亮度数值、滑块和复选框的绘制都在遮罩内完成，选择框也已绘制；返回时遮罩为 0。仍检查位置/尺寸不变、无延迟重排和已可见时不重复显示。该检查使用示例状态；不切换真实 HDR、SDR、杜比视界或 RTX 设置。自动检查验证原生窗口与绘制时序，不等同于高帧率桌面录像。

## 0.18 托盘唤起修复

修复隐藏面板唤起时先在临时位置显示，再移动到工作区底部并延迟重排的问题。现在在隐藏状态创建窗口、移至目标屏幕以更新 DPI，完成缩放、布局和定位，再显示并同步绘制完整客户区。首次加载也使用同一目标工作区；唤起期间抑制几何定时器，取消显示后的延迟定位。明确打开一个已经可见的面板时，不再次显示或重新定位。

新增 `--popup-opening-test 路径.txt`，使用示例数据检查冷启动、同屏重复唤起和跨屏唤起。100% / 150% / 175% 三种 DPI 共 18 次唤起，原生窗口实际变为可见时的边界已等于最终边界，显示后位置/尺寸变化为 0，没有安排延迟重排。托盘收起、RTX 层级保护、720 次亮度拖动、布局及基础自检通过。本轮没有改动真实显示设置；原生窗口检查未逐帧分析桌面合成器输出。

## 0.17 托盘单击修复

控制中心可见时，左键单击托盘图标直接隐藏；隐藏时，单击打开。不再要求控制中心拥有键盘焦点。因此点击“Windows HDR 设置”或“NVIDIA 视频设置”后，即使焦点在外部窗口，也只需要一次托盘点击即可收起，不会先激活或移动控制中心。RTX 操作期间/结束后的窗口保护仍允许这一主动收起，并恢复原来的窗口层级。右键菜单“打开控制中心”继续明确唤起面板。

新增窗口回归在修改前复现失焦后的第一次点击未能收起；修复后验证普通面板及 RTX 保护面板均一次收起，不产生激活、重新定位、尺寸变化或句柄重建；下一次单击重新打开。连续亮度拖动、绘制/键盘和原有窗口生命周期回归均通过。本轮使用另一测试窗口模拟控制面板焦点转移，没有打开真实控制面板或更改显示设置。

## 0.16 亮度调节修复

修复连续拖动 SDR 亮度时显示器选择框闪烁的问题。亮度数值使用固定宽度显示区，变化时只重绘数值，不触发整张表格重新布局；宽度在字体和 DPI 改变后重新计算。原有实时亮度写入管线保持，每次拖动位置仍可异步写入，松开后确认最终值。

显示器选择框改为在内存缓冲里完整绘制后一次提交，不再先画原生方框再覆盖圆角。保留原生下拉菜单、键盘选择和显示器记忆。普通设置通知不再无条件重排整个窗口，工作区、DPI 和显示模式变化仍走原有恢复路径。绘制依据：[Microsoft WM_PAINT](https://learn.microsoft.com/en-us/windows/win32/gdi/wm-paint)。

新增回归在修改前复现：120 次连续数值变化造成 120 次选择框重绘。修复后，两套主题、100% / 150% / 175% 三种 DPI 共 720 次拖动位置更新，选择框重绘、无效区域通知、位置/尺寸变化及选择变化均为 0；亮度数字逐次更新，数值区域尺寸稳定，DPI 往返后宽度符合当前字体。原有布局、绘制/键盘和 RTX 窗口层级回归通过。桌面示例窗口检查了原生下拉菜单打开/关闭和滑块拖动。该轮使用示例数据，不更改真实 HDR、SDR、杜比视界或 RTX 设置，也未重新验证真实驱动的亮度写入。

## 圆角界面

窗口采用一体化标题区、圆角卡片、圆角开关和按钮，移除原来的白色系统标题栏。在标题区拖动窗口，边缘可调整大小；右上角关闭按钮仍隐藏到托盘。Windows 11 使用系统圆角；旧系统不保证相同的外部圆角和阴影。圆角实现依据：[Microsoft 自定义窗口框架](https://learn.microsoft.com/en-us/windows/win32/dwm/customframe)。

控制中心跟随 Windows 的应用深浅色主题，运行时收到主题通知或定期检查后更新，不修改系统主题设置。托盘使用透明背景的显示器与调节线轮廓，按系统任务栏深浅色使用浅色/深色笔画；程序图标为蓝色轮廓。高对比度模式使用系统颜色。

0.15 修复 0.14 中按钮旁出现重复状态文字、复选框和提示叠影、按钮边角残留的问题：按钮和复选框使用完整自绘控件，每次重绘清除自己的背景；文字采用 GDI+ 绘制，关闭残留原生窗口框架绘制。保留键盘空格/回车、焦点和辅助功能默认动作。原有 HDR、杜比视界、NVIDIA 操作管线和 RTX 窗口层级保护继续使用。

本轮实际窗口检查包含深浅色切换、勾选与空格键操作、真实显示器/RTX 状态读取及刷新。自动回归覆盖背景残留、文字可见、键盘/辅助功能操作、100% / 150% / 175% DPI 往返排版，以及 RTX 的窗口可见性和层级保护。测试未切换真实 HDR、杜比视界或 RTX 开关；本轮没有重新进行物理插拔、睡眠或真实 RTX 切换验证。

升级时先通过旧版托盘菜单“退出”，解压整个新版目录后运行其中的 EXE。显示器选择和杜比守护设置沿用原配置。若更换存放目录，需要在新版重新勾选登录启动以更新启动路径。

## 使用

1. 先把整个目录解压到固定位置，再运行 EXE。
2. 选择显示器。选择会按显示器设备路径保存在 `%LOCALAPPDATA%\HdrControlCenter\settings.json`，重新打开自动恢复。原显示器断开时要求重新选择，避免把操作误应用到另一块屏幕。
3. HDR 开关和 SDR 内容亮度直接控制当前所选显示器。亮度支持鼠标、键盘和滚轮调整。首次移动立即异步写入，连续拖动时约每 30 ms 合并一次最新值；每次都实际提交给 Windows，鼠标仍按住时亮度也会变化。松开后立即提交最终值并回读确认；若前一次写入尚未完成，完成后立即处理松开时的最新值。后台刷新不会禁用滑块或把位置拉回。0–100% 对应 80–480 nits 的 SDR 参考白亮度；这是 Windows HDR 内容亮度，不是显示器背光亮度。更新速度仍受系统/驱动写入耗时限制。
4. 勾选“登录 Windows 时启动”，即可在当前用户登录时静默启动到托盘。此时移动 EXE 会导致启动路径失效，应从新位置运行并重新勾选。取消勾选可移除本软件的启动项。
5. 单击右下角显示器轮廓图标打开快捷面板；右键打开菜单。关闭面板仍驻留托盘，通过右键“退出”结束程序。Windows 可能把图标放在托盘折叠区，可在系统任务栏设置中把它设为显示。

请保留 EXE 旁的 `HdrControlCenter.exe.config`，这是动态 DPI 支持所需的运行配置。显示器插拔、缩放变化和工作区变化后，工具重新按当前屏幕 DPI 排版，并限制窗口在屏幕可用范围内；小屏幕内容可滚动。在不同缩放屏幕之间移动时，宽度按逻辑尺寸重新计算，避免反复缩放后越来越小。手动调整的窗口宽度在本次运行中保留。

## 杜比视界

杜比视界是 Windows 选择的 HDR 输出模式，只有支持的系统、驱动和 Dolby Vision 认证显示器才会提供开关。

直接点击“切换…”。工具会自动打开或恢复 Windows HDR 设置，选择工具中选中的显示器，展开 HDR 选项并操作“使用 Dolby Vision 模式”的真实复选框。沿用原有控件操作路径，通过 `ms-settings:display-hdr` 进入正确页面，并等待页面、显示器列表和开关加载；Windows 重建控件时重新获取，不复用失效控件。显示器型号按完整名称匹配，避免相似名称误选。

操作前没有设置窗口时，切换成功并回读确认后自动关闭本次打开的设置窗口；原先已打开的窗口（包括最小化的窗口）保留。失败时保留页面便于查看原因。关闭时核对本次窗口的原生句柄和进程；对于 ApplicationFrameHost 托管窗口，还会确认其子窗口属于 SystemSettings，不结束设置进程。状态在关闭前保存，随后显示“上次确认”的开关状态，关闭页面后不声称实时读取到杜比视界状态。

多显示器环境下会按唯一的显示器型号匹配系统下拉列表，并回读确认选中项。名称重复或通用名称“显示器”不能安全匹配时，会拒绝操作并说明原因。未找到选项时显示未知，并给出具体原因，不把“未找到”当成“不支持”。读取到的是输出模式开关，不是视频正在播放 Dolby Vision 的检测结果。

### 始终关闭杜比视界

选择目标屏幕，勾选“始终关闭杜比视界（所选显示器）”。此设置会保存。勾选后先修复一次，后续在程序启动、显示器重新连接、会话屏幕重新点亮、睡眠恢复或解锁时，等待屏幕稳定约 2 秒，再执行一次 **开启 → 等待 → 关闭 → 回读确认**。用于绕过“实际开启但 Windows 复选框显示关闭”的状态不同步：即使读取的初始状态为关闭，也会执行这一轮切换。

隐藏到托盘或使用登录启动时仍运行。需要软件保持运行、所选屏幕在线并已启用 HDR，且系统提供可操作的 Dolby Vision 选项；屏幕断开或 HDR 关闭时等待恢复。连接状态每 1.5 秒读取一次，并结合显示变化、会话电源及恢复通知；Windows 未通知的独立显示器熄屏/点亮、以及未改变连接状态的显示器硬件操作可能无法检测。

开启期间，杜比视界按钮变成“修复关闭”，可手动补执行一次。取消勾选会停止后续自动操作；已经开始的开启→关闭仍完成关闭，退出程序也会等待本次关闭结束。失败会显示原因、记录日志，并最多重试 3 次；显示器名称无法唯一匹配时不会操作其他屏幕。

该功能通过真实 Windows HDR 设置复选框完成，系统设置可能短暂打开，显示器可能短暂黑屏。成功后仅关闭由这次操作新建的设置窗口，原先打开的窗口保留。切换产生的显示变化通知会被合并和抑制，避免自我触发。它是重新连接/点亮后的恢复操作，不是阻止 Windows 在驱动层启用 Dolby Vision 的系统策略。

## NVIDIA RTX 视频增强

可以直接点击 RTX 功能旁的快捷开关，无需先手动打开控制面板。工具自动启动控制面板、定位“调整视频图像设置”、读取当前开关、切换并应用。支持的驱动在控制面板关闭后也可从保存配置回读开关状态。商店版 / DCH 通过 Windows 注册的应用 ID 启动，不要求访问受保护的 WindowsApps 安装目录。也可从托盘右键菜单指定传统版 `nvcplui.exe` 路径。

每次快捷操作最多主动启动控制面板一次。应用后优先核对驱动保存值；页面仍在时也可通过控件回读。操作前没有打开的 NVIDIA 页面时，成功后清理本次唤起的窗口；原先打开的窗口不主动关闭。驱动自行关闭窗口时不重开，识别到保存配置即可显示“已开启/已关闭”；驱动自己关闭原有窗口的行为不由工具控制。不支持保存配置读取且页面已关闭时，仍明确显示“已提交，待确认”，下次连接通过页面回读。已有待保存修改时会在导航和切换前拒绝操作。

NVIDIA 根元素由该进程的原生窗口句柄获取，不再遍历所有桌面 UIA 根元素来寻找它。设置前捕获操作窗口的 HWND、PID 和进程启动时间。清理只操作这一身份，并在发送关闭消息前重新验证；窗口已销毁或变为不可见时直接视为清理完成。窗口仍存在但 UIA 控件暂时失效时，有界重试新控件；有待保存修改或仍无法确认时保留窗口。关闭请求只发送一次，并等待原生窗口关闭结果，等待超时会说明窗口已保留。

清理失败与设置失败分开：已确认的 RTX 开关不因窗口清理异常被丢弃。结果区保留“设置已应用；窗口未能关闭”等简短说明，后台刷新不会覆盖它。RTX 操作失败也显示简短行内提示，完整堆栈写入日志，不再弹出会影响面板焦点的错误对话框。UIA 失效处理依据：[Microsoft ElementNotAvailableException](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.elementnotavailableexception?view=windowsdesktop-10.0)。

RTX 操作开始时若控制中心面板已打开，会保持这一个窗口。非主动隐藏和关闭在发生前被拦截，包括绕过 `SetVisibleCore` 的原生 `WM_SHOWWINDOW` / `WM_WINDOWPOSCHANGING` 消息。保护不会在工作线程返回时立即撤销，以覆盖 NVIDIA 关闭后延迟到达的消息；通过托盘或标题栏主动隐藏仍生效，下次主动唤起后再使用快捷操作时继续保护。操作结束仅更新状态，完全不调用显示、恢复最小化、激活或额外几何重排，不抢回焦点。只有主动单击托盘图标或“打开控制中心”才会唤起面板。窗体和布局容器采用双缓冲，状态更新合并布局；显示器列表未变化时原位更新，不清空重建。几何检查没有实际改变窗口边界时不强制整窗重绘。操作期间选择退出会等待结束后退出；Windows 关机请求正常放行。关闭 NVIDIA 窗口时使用原生窗口句柄并核对所属进程，只向 `nvcplui` 窗口发送关闭消息，不再通过 UI Automation 窗口代理关闭。

0.12 不再把任意 `SC_CLOSE` 当成用户点击关闭。保护期间，只有观察到控制中心自身的标题栏关闭/系统菜单输入或 Alt+F4，才允许该系统命令隐藏到托盘；没有对应输入的关闭命令被拦截并记录。托盘主动隐藏及“退出”仍正常工作。

0.13 补上窗口层级保护：RTX 操作开始前，已打开且未最小化的面板通过 `SetWindowPos(HWND_TOPMOST)` 临时置顶，并使用 `SWP_NOACTIVATE | SWP_NOMOVE | SWP_NOSIZE | SWP_NOOWNERZORDER`。NVIDIA 获得焦点和关闭后，面板仍保持这一层级，直到用户主动隐藏/关闭面板时恢复此前的普通/置顶层级。这样不会在操作完成时降到其他窗口后面，也不用反复 Show 或 Activate。隐藏到托盘时发起的操作不打开面板、不设置置顶；用户主动最小化不会被恢复。该置顶只持续本次面板显示，不新增持久的全局置顶设置。接口依据：[Microsoft SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。

原生拦截依据：[Microsoft WM_SHOWWINDOW](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-showwindow)、[Microsoft WM_WINDOWPOSCHANGING](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-windowposchanging)。通过在变更前去掉隐藏标记/阻止默认所属窗口隐藏处理保留窗口，不采用定时重新显示。

保存配置读取为只读操作，按 NVIDIA 显卡的实际驱动键匹配，不修改注册表。Super Resolution 使用质量档位（0 关闭，1–4 手动档，5 自动档）；仅识别已知 HDR 值及启用标记，未知格式不会猜测。缺失配置、权限不足、多块 NVIDIA 显卡无法唯一匹配时回退到控制面板读取。因此不能保证所有驱动都能无窗口读取。读取的是已保存开关，视频增强是否正在处理视频仍需要控制面板提供活动状态文字。

本版通过 UI Automation 读取 Super Resolution 与高动态范围复选框，切换后等待控制面板动态创建“应用”按钮，再调用它并回读状态。兼容“应用(A)”“应用(&A)”“Apply”等名称。这些设置不跟随本工具的显示器选择。高动态范围指 **RTX Video HDR**，不包含游戏 RTX HDR。

注意当前实现的兼容边界：

- 本版采用自动操作控制面板的路径，切换时窗口可能短暂出现；不是无界面驱动 API 实现。活动状态实时读取仍需控制面板提供可访问的状态文字。页面关闭后优先读取驱动已保存的开关，并把活动状态标为未检测；无法读取时保留上次确认或标为待确认。
- 支持简体中文、繁体中文和英文的已知控件名称。驱动版本、语言、控件结构不同，可能无法识别；此时会禁用操作并显示未知。
- 控制面板已有待应用的其他修改时，工具拒绝快捷切换，避免替你应用其他设置。
- “已开启/已关闭”来自开关，“正在生效/未生效”来自驱动页面的状态文字。只读取独立功能组或紧邻各自开关下方的状态文字，避免把另一项功能的状态混入；无法明确归属时显示未知。兼容“非活动”等中文状态。启用不代表当前视频符合增强条件，也不代表当前视频正在使用增强。
- 未实现 NVIDIA App 的界面适配。可以通过 NVIDIA 控制面板连接。

## 构建和诊断

源代码在 `src` 下。用 PowerShell 运行 `build.ps1`，通过 Windows 自带 .NET Framework C# 编译器生成 x64 EXE。构建不下载依赖。

只读检查，可在命令行指定输出路径：

```powershell
.\HdrControlCenter.exe --self-test C:\path\self-test.txt
.\HdrControlCenter.exe --diagnose C:\path\diagnostics.txt
```

`--diagnose` 不修改显示器状态，也不打开控制面板。`--preview 路径.png` 生成带示例数据的界面预览，不写入系统设置。错误日志保存在 `%LOCALAPPDATA%\HdrControlCenter\errors.log`。

`--layout-test 路径.txt` 在各在线屏幕上测试 DPI、显示变化恢复、工作区边界及控件重叠，使用示例数据，不切换 HDR 或杜比视界。自动关闭的开始和结果记录在 `%LOCALAPPDATA%\HdrControlCenter\recovery.log`，可用来判断物理插拔是否触发修复。日志到约 200 KB 后轮换。

`--panel-lifecycle-test 路径.txt` 使用示例数据检查 RTX 操作期间的面板关闭拦截、完成后恢复与主动隐藏，不操作驱动。

0.9 扩展此检查：已经显示的面板在普通操作完成后不改变可见性、窗口句柄、边界，不额外安排几何重排；状态刷新保留显示器选中对象，显示器断开仍正确清空选择。

需要诊断窗口闪烁时，可使用独立测试实例 `--test-ui --panel-trace 路径.txt` 记录可见性、尺寸、句柄、实际几何变化及 RTX 操作边界。此模式在内存中禁用自动杜比视界守护，避免 RTX 测试触发它；点击 RTX 开关仍会真正修改驱动设置，请在测试后恢复原值。

删除软件前，先取消登录启动并从托盘退出，再删除文件。需要清理配置时可删除 `%LOCALAPPDATA%\HdrControlCenter`。
